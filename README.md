# ⚡ Pokédex

## Explore. Discover. Gotta know them all.

### A modern, responsive Pokédex built with React and PokéAPI, featuring intelligent search, detailed Pokémon data, version-aware move filtering, dark mode, responsive layouts, and smooth Motion-powered interactions.

# ✨ Features

- 🔎 **Pokémon Search** — Search through the PokéAPI database with autocomplete suggestions.
- ⌨️ **Keyboard Navigation** — Navigate suggestions with `↑` / `↓` and select with `Enter`.
- 🖼️ **Pokémon Sprites** — Visual Pokémon previews inside search suggestions.
- 📖 **Pokémon Information** — View types, abilities, descriptions, and other Pokémon data.
- 📊 **Base Stats** — Explore Pokémon statistics in a dedicated interface.
- ⚔️ **Move Explorer** — Browse moves by learning method and game version.
- 🎮 **Version-Aware Filtering** — Only display versions where the selected Pokémon actually has available moves.
- 🎵 **Pokémon Cries** — Listen to Pokémon cries directly from the application.
- 🌓 **Dark / Light Mode** — Switch between custom light and dark themes.
- 🎞️ **Smooth Animations** — Interactive transitions and layout animations powered by Motion.
- 📱 **Responsive Design** — Designed for both desktop and mobile devices.
- ⏳ **Loading States** — Clear feedback while Pokémon data is being fetched.
- ❌ **Error Handling** — Dedicated error states for unsuccessful searches or API failures.

# 🧠 What I Learned

Building Pokédex gave me hands-on experience with several areas of modern frontend development.

### ⚛️ React

- Building reusable components
- Managing state and props
- Controlled inputs
- Conditional rendering
- Component composition
- Passing content through `children`
- Designing state-driven interfaces
- Breaking larger components into focused components

### 🧩 JavaScript & Data Manipulation

A major part of the project was learning how to work with **large and deeply nested datasets**.

PokéAPI provides significantly more information than the UI actually needs, so I learned to transform and filter the data before presenting it.

This included working with:

- `map()`
- `filter()`
- `some()`
- `find()`
- `Promise.all()`
- Nested arrays and objects
- Short-circuit evaluation
- Extracting specific information from large API responses

One example was filtering game versions based on whether a Pokémon actually has moves available in that version, rather than simply displaying every version returned by the API.

### 🌐 API Integration

- Working with REST APIs
- Handling asynchronous requests
- Managing loading and error states
- Understanding complex API response structures
- Transforming API data into UI-friendly structures
- Avoiding unnecessary API requests

### 🎞️ Motion

This project gave me my first deeper experience with **Motion**.

I learned how to use:

- `initial`
- `animate`
- `exit`
- `whileHover`
- `whileTap`
- `AnimatePresence`
- `layout`

One of the most useful concepts was **layout animation** — allowing Motion to smoothly animate elements when their position changes because surrounding content changes size, instead of manually calculating their new positions.

### 🎨 UI / UX

- Designing autocomplete interactions
- Keyboard navigation
- Responsive layouts
- Dark mode
- Loading and error feedback
- Micro-interactions
- Information hierarchy
- Using animation to improve continuity and feedback

# 🎨 Design Philosophy

### Keep the interface focused

PokéAPI contains a huge amount of information. Pokédex focuses on presenting the information that is actually useful to the user.

### Let the data shape the UI

Rather than displaying raw API responses, the application extracts and transforms the data into structures designed around the user experience.

### Make interactions feel intentional

Animations are used to provide feedback and maintain visual continuity, rather than simply adding motion for decoration.
